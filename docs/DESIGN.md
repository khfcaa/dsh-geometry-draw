# 设计说明

这份文档记录**为什么这么写**。源码注释讲局部判据，这里讲整体取舍；
改代码前读它，能避免把已经决定过的事再翻一遍。

## 为什么是「声明式规格」而不是「绘图脚本」

让模型写绘图脚本（哪怕是 `matplotlib`）有三个稳定的失败模式：结果不可复现、
无法自检、以及把几何问题变成编程问题。声明式规格把这三件事都收回来：

- **可复现**：规格是纯数据，同样的输入必然得到同样的 SVG（内容哈希可直接当文件名）。
- **可自检**：编译前就能检查退化轮廓、自交、填充规则隐患、内容越界——
  这些恰恰是缩略图上肉眼看不出来的问题。
- **几何归几何**：布尔运算、偏移、阵列由内核统一算，不在每次生成时重新发明。

## 为什么自己写几何内核

需求里有三件事是现成 SVG 做不到的：

| 需求 | 为什么不能只靠 SVG |
|---|---|
| 布尔运算取**真实孔洞** | SVG 没有布尔运算；`clip-path` 会留下裁剪痕迹，且无法参与后续偏移 |
| 轮廓偏移 | SVG 没有 offset 路径；`stroke-width` 做出来的环带内外不均匀，且端点会露 |
| 多轮廓的**可靠**填充 | 多轮廓靠奇偶规则隐式解释，方向错了孔洞就被填实，且没有 warning |

所以内核里有三层：`path.js` 把任意 SVG 路径展平成直线段（弧 → 三次贝塞尔 → 折线），
`geometry.js` 在直线段上做精确布尔与偏移，`compiler.js` 把结果重新输出成标准 SVG。
曲线的离散误差因此被限制在「0.1 屏幕像素」这一个明确的地方。

## 布尔运算的三条判据（踩过的坑）

`src/geometry.js` 里最贵的知识。想改这段代码，请先理解这三条：

1. **子段中点贴在自己的边界上。** 判断「这条子边在内还是在外」时，
   取子段中点去测是**抛硬币**——它正好落在边界上。正确做法是在两侧各取一个候选点，
   再用「谁在自己的环内」来定，而不是靠法线方向推理。
2. **外侧探针的符号方向。** `leftNormal(a) = [a[1], -a[0]]` 返回的其实是**右**法线
   （函数名是历史遗留，`src/math.js` 有注释）。偏移与探针的符号都是按这个事实定的。
3. **缝合依赖端点 key 的一致性。** 两条边在共享顶点上的坐标可能相差 `1e-16`，
   用浮点坐标当 key 就缝不起来。所有端点先吸附到 `1e-9` 网格再做 key。

另外，XOR 实现为 `(A−B) ∪ (B−A)`，不是直接按「奇偶」筛边——
早期版本那样做会得到方向混乱、无法缝合的边界。

## 为什么坐标是数学坐标

x 向右、**y 向上**。屏幕坐标的直觉（y 向下）是这个工具里最容易犯的错，
所以：

- 规格全程用数学坐标，**只在渲染那一步**翻转一次；
- 文字与标签在翻转**之外**绘制，否则字形会上下颠倒；
- `label_offset` 是唯一按屏幕像素给的地方（y 向下），单独标注在文档与类型描述里。

## 为什么错误与警告分开

- **抛错**：规格本身不合法（未知元素类型、未定义的点引用、路径越界）。
  这类问题修了才能出图。
- **warning**：几何上合法、但结果大概不是你想要的（退化轮廓、自交、
  多轮廓没声明填充规则、内缩把形状缩没了、内容跑出可视范围）。

这个分界让 `audit: false` 有意义：批量生成时你只想拿图，不想被警告刷屏。

## 为什么工具描述里内联了构图要点

`index.js` 的 `SPEC_HELP` / `COOKBOOK` 与 `skills/free-form-geometry/SKILL.md` 说了同一件事。
这是**刻意的重复**：随包技能树只有在宿主能解析 `@deepseek-ai/dsh-skill-filesystem`
时才会挂载（打包成 `app.asar` 时经常解析不到），而工具描述一定会到模型手里。
挂不上技能时，模型照样知道「孔洞要用 difference 挖，不要拿白色形状盖」。

两处内容改动时要同步。

## DSH 集成的几个硬约束

1. **工具输出 schema 是受限子集。** `type` 必须是单个字符串；允许的关键字只有
   `type/oneOf/properties/required/additionalProperties/items/enum/const`。
   写 `type: ["string","null"]` 会让**整个插件激活失败**（`JsonSchemaError`），
   而不是仅仅丢一个字段。可选字段因此用 `''` / `0` 表示「无」。
2. **bundle 只在进程启动时装载。** 改完 profile 必须重启 DSH；运行中不会热生效。
3. **桌面版 profile 由 Electron 应用独占。** 手工 `dsh --profile desktop` 会被拒绝。
4. **模块按真实路径解析。** 插件以 `file:`/`link:` 安装时，`import '@resvg/resvg-js'`
   会从插件源码目录找依赖而找不到。所以 `index.js` 显式从
   `DSH_PROFILE_DIR/node_modules` 等候选位置解析——`tests/load-resvg.mjs` 是同一套逻辑的
   测试版。

## 为什么零运行时依赖

这个插件要能装进任何一个 DSH profile，包括离线环境。
几何、表达式求值、SVG 生成全部自写；唯一需要的外部能力是 PNG 栅格化，
而复用宿主已有的 resvg 不增加安装负担（装不上时工具仍能出 SVG，只是附一条 warning）。
